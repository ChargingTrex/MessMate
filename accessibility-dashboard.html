Open findings (6)

CRITICAL

F1 — Pause, Stop, Hide

SC 2.2.2 · Level A

/home — .ticker-section

The ticker scrolls on a 38s infinite loop with no pause, stop or hide control. A CSS hover-pause exists but is unreachable by keyboard or touch.

Measured: animation: tickerScroll 38s linear infinite; 0 controls in the region

Fix: Add a visible pause toggle to the ticker that sets animation-play-state, and expose it as a real button.

<button type="button" id="tickerPause" class="ticker-pause"
        aria-pressed="false" aria-label="Pause scrolling notices">⏸</button>

/* CSS */
.ticker-section.is-paused .ticker-content { animation-play-state: paused; }
CRITICAL

F2 — Non-text Content

SC 1.1.1 · Level A

/dashboard, /dashboard/committee — every <canvas>

Chart canvases carry no aria-label, no role and no fallback content, so a screen-reader user gets nothing where a sighted user gets the trend.

Measured: canvas#trendChart: aria-label=null, role=null, fallback=''

Fix: Give each canvas role="img" and an aria-label that states what the chart shows, generated from the same data the chart plots.

<canvas id="trendChart" role="img"
        aria-label="Line chart: average daily score over the last 7 days, 3.6 to 4.1 out of 5."></canvas>

// keep it true as data changes
canvas.setAttribute('aria-label',
  `Line chart: average daily score over the last ${n} days, ${min} to ${max} out of 5.`);
CRITICAL

F3 — Labels or Instructions / Name, Role, Value

SC 3.3.2 / 4.1.2 · Level A

/ (rating form) — textarea#review, input[name=suggestion]

Both controls rely on a placeholder alone. Placeholders are not accessible names, and they vanish on input.

Measured: textarea#review: label=false, aria-label=null, placeholder only

Fix: Add a visible <label for>, or an aria-label where the design has no room.

<label class="item-label" for="review">Comments about today's lunch</label>
<textarea id="review" name="review" ...></textarea>

<input name="suggestion" aria-label="Suggest a dish for the mess menu" ...>
SERIOUS

F4 — Contrast (Minimum)

SC 1.4.3 · Level AA

/ and /committee/login — header subtitle, .char-counter, .subtext

Four distinct foreground/background pairs fall below 4.5:1 for normal text. All are on the light-theme student pages.

Measured: header p (white @ opacity .9 on #2E75B6) = 4.25:1 · .char-counter #888888 on #ffffff = 3.54:1 · .subtext #777777 on #f7f9fc = 4.25:1 · on #ffffff = 4.48:1

Fix: Drop the header's opacity (white on #2E75B6 is 4.84:1), and move both greys to #6e6e6e, the lightest value that clears 4.5:1 on BOTH light backgrounds (5.10:1 on #ffffff, 4.83:1 on #f7f9fc).

header p { opacity: 1; }          /* 4.25:1 -> 4.84:1 */
.char-counter { color: #6e6e6e; } /* 3.54:1 -> 5.10:1 */
.subtext,
.subtext-line { color: #6e6e6e; } /* 4.25:1 -> 4.83:1 on #f7f9fc */
SERIOUS

F5 — Use of Colour

SC 1.4.1 · Level A

/dashboard/committee — committee trend chart

When more than one series is enabled, the only thing distinguishing the lines is their colour; the legend maps colour to name and nothing else does. Manifests only once a user switches a second series on.

Measured: 5 dimension datasets differ by borderColor alone — no dash pattern, no point style, no direct label

Fix: Give each series its own dash pattern and point style as well as colour, so the legend is not the only key.

const SERIES = [
  {borderDash: [],      pointStyle: 'circle'},
  {borderDash: [6, 3],  pointStyle: 'triangle'},
  {borderDash: [2, 2],  pointStyle: 'rect'},
  {borderDash: [8, 3, 2, 3], pointStyle: 'rectRot'},
  {borderDash: [1, 3],  pointStyle: 'cross'},
];
MODERATE
